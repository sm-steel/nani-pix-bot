## Обновления

Каждый релиз публикует образ с номером версии в `ghcr.io/sm-steel/nani-pix-bot`.
Что изменилось — на странице [Releases](https://github.com/sm-steel/nani-pix-bot/releases)
или здесь, в разделе [Что нового](/nani-pix-bot/ru/whats-new/).

Как выкатывать обновления — решать вам. Подойдёт любой вариант:

- `docker compose pull && docker compose up -d`
- небольшой скрипт или свой CI/CD
- инструмент вроде [Watchtower](https://containrrr.dev/watchtower/)

Бот сам обновляет базу данных при каждом запуске, так что о миграциях помнить не
нужно.

## Проверка здоровья и автоперезапуск

У контейнера бота есть проверка здоровья, которая следит за успешной связью с
Telegram: если бот перестал получать обновления, хотя процесс ещё жив, контейнер
помечается как нездоровый. Docker проверяет это каждые 30 секунд и помечает
контейнер нездоровым, если три проверки подряд не видят связи с Telegram дольше
90 секунд.

`restart: unless-stopped` в `docker-compose.yml` и так восстанавливает работу
после большинства сбоев. А для тех, кто запускает наблюдатель вроде
[docker-autoheal](https://github.com/tmknight/docker-autoheal), который
перезапускает нездоровые контейнеры, у сервиса `bot` есть метки `autoheal`. Без
такого наблюдателя эти метки ни на что не влияют.
