## Updating

Every release publishes a versioned image to `ghcr.io/sm-steel/nani-pix-bot`. See
the [Releases](https://github.com/sm-steel/nani-pix-bot/releases) page for what
changed, or the [What's new](/nani-pix-bot/whats-new/) page here.

How you roll updates out is up to you. Any of these work:

- `docker compose pull && docker compose up -d`
- a small script or your own CI/CD
- a tool such as [Watchtower](https://containrrr.dev/watchtower/)

The bot updates its database by itself on every start, so there's no migration
step to remember.

## Health checks and auto-restart

The bot's container has a health check that watches for successful contact with
Telegram, so it's marked unhealthy if the bot stops receiving updates even though
the process is still running.

`restart: unless-stopped` in `docker-compose.yml` already recovers from most
failures. The `bot` service also carries `autoheal` labels for anyone running a
watcher such as [docker-autoheal](https://github.com/tmknight/docker-autoheal),
which restarts unhealthy containers. Without such a watcher, the labels do nothing.
